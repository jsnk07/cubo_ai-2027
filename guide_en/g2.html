F2.1Writing effective instructions

A prompt is a specification. The clearer you are about what you expect, the less the model has to guess. Before writing it, define what a good answer looks like: its format, its length and what it must not include.

A structure that works in almost every case:

  • Role and context: who it is for and in what situation it will be used.
  • Task: what it has to do, with a clear verb (classify, summarize, extract, compare).
  • Input data: the text or information, separated with clear markers (for example, between tags or triple quotes).
  • Output format: list, table, JSON with defined fields, number of words.
  • Examples: one or two solved cases (few-shot) when the format or criterion is not obvious.
  • Constraints: what to do if it doesn't know (“answer not found”), what not to invent.

The first prompt is rarely the right one. Work in rounds: test, see where it fails, change one thing at a time and test again with the same cases. That way you know which change improved the result.

Key ideas
  • Define the result before writing the prompt.
  • Change one thing at a time and always test with the same set of cases.
  • Give the model an honest way out for when it doesn't know.
Think about itWhat instruction would you give a new person at your job so they do a task well on day one? What is your prompt missing compared with that?

F2.2Auditing responses and detecting bias

Verifying is not rereading the answer to see if it “sounds right”. It is comparing it with something you know is true. Some practical techniques:

  • Reference answers: prepare cases with a known correct answer and measure how many the model gets right.
  • Sources: ask it to cite where each fact comes from and check that the source exists and says that.
  • Consistency: ask the same question in several ways or several times; if the answer changes, be suspicious.
  • Counterfactual bias tests: change only one attribute (name, gender, area of residence) and see whether the model's decision changes.

Bias can come from the model's training data, from the data you give it or from the way you frame the task. That is why the audit checks all three.

Key ideas
  • Without reference cases there is no way to measure quality.
  • Changing a single attribute is the simplest and most revealing bias test.
Think about itIf an assistant evaluates scholarship applications, which attribute would you change first to test whether it is fair?

F2.3Assisted ideation methods

AI is very good at generating many options quickly and bad at choosing the right one for you. Use it in the phases where quantity helps, and decide yourself where judgment matters:

  1. Diverge: ask for 20 ideas, different approaches or the perspectives of several stakeholders (user, operator, regulator).
  2. Cluster: ask it to organize the ideas by theme or type of solution.
  3. Critique: ask for the arguments against each idea, or have it act as a skeptical reviewer.
  4. Decide: you choose, with explicit criteria such as impact, feasibility and risk.

Record which ideas came from AI and which from the team. In the defense you will be asked why you chose a path, and “the model suggested it” is not a reason.

Key ideas
  • Diverge with AI, decide with human criteria.
  • Asking for critiques is as useful as asking for ideas.
Think about itWhat criterion would you use to discard an idea the model presents as excellent?

F2 · Self-assessmentCheck what you learned

Name four parts of a well-structured prompt.

Role and context, task, delimited input data, output format, examples and constraints (any four).

Why change only one thing at a time when improving a prompt?

So you know which change caused the improvement or the decline when you compare against the same cases.

What is a counterfactual bias test?

Repeating the same input changing only one attribute, such as name or gender, to see whether the model's decision changes.

What is few-shot?

Including one or a few solved examples in the prompt to show the model the expected format or criterion.

In an ideation session, which part should you not delegate to AI?

The final decision, which must rest on the team's explicit criteria.

DIY WORKSHOP · F2

Prompt lab with evidence

Design a prompt repertoire for a real task, test it with reference cases and audit it for bias. Produces the F2 deliverable.

3–4 hoursIndividual or in pairsTechnical: Docker + Ollama
Technical route
Evaluate prompt variants with a script
  1. Choose a classification task, for example sorting citizen queries into procedure, complaint, information or other.
  2. Write 20 cases in cases.csv with the correct label. Use made-up texts, without personal data.
  3. Write three versions of the prompt in prompts/v1.txt, v2.txt and v3.txt: a basic one, one with a fixed output format and one with two examples (few-shot).
  4. With the F1 model in Ollama, write evaluate.py: for each version and each case, request the label with "options": {"temperature": 0} and compare it with the correct one. Print each version's accuracy.
  5. Bias test: take five cases, change only the writer's name or gender and check whether the label changes.
  6. Commit each version of the prompt so the history shows how you improved.
Complementary route
Prompt repertoire and quality rubric
  1. Choose three tasks from your discipline: for example, summarizing a report, drafting a reply to a user and extracting data from a document.
  2. For each task, write the prompt with the F2.1 structure and define a 1-to-3 rubric for accuracy, format and tone.
  3. Test each prompt with five different inputs in an AI assistant and score each answer with your rubric.
  4. Improve the lowest-scoring prompt and test it again with the same five inputs.
  5. Audit one case: change a personal attribute in the input and document whether the answer changed.
Deliverable

A repertoire of validated prompts (with their final version, purpose and score) and a one- to two-page audit report on the accuracy and bias observed in the case study.

Checklist
  • Each prompt has test cases and a measured result.
  • You can show the previous version and explain what changed.
  • The bias test changes a single attribute.
  • You did not use real personal data.
