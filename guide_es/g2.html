F2.1Formulación efectiva de instrucciones

Un prompt es una especificación. Cuanto más claro sea lo que esperas, menos tiene que adivinar el modelo. Antes de escribirlo, define cómo se verá una buena respuesta: su formato, su extensión y qué no debe incluir.

Una estructura que funciona en casi todos los casos:

  • Rol y contexto: para quién es y en qué situación se usará.
  • Tarea: qué tiene que hacer, con un verbo claro (clasificar, resumir, extraer, comparar).
  • Datos de entrada: el texto o la información, separada con marcas claras (por ejemplo, entre etiquetas o comillas triples).
  • Formato de salida: lista, tabla, JSON con campos definidos, número de palabras.
  • Ejemplos: uno o dos casos resueltos (few-shot) cuando el formato o el criterio no son obvios.
  • Restricciones: qué hacer si no sabe (“responde no encontrado”), qué no inventar.

Rara vez el primer prompt es el bueno. Trabaja en vueltas: prueba, mira dónde falla, ajusta una cosa a la vez y vuelve a probar con los mismos casos. Así sabes qué cambio mejoró el resultado.

Ideas clave
  • Define el resultado antes de escribir el prompt.
  • Cambia una cosa a la vez y prueba siempre con el mismo conjunto de casos.
  • Dale al modelo una salida honesta para cuando no sabe.
Para pensar¿Qué instrucción le darías a una persona nueva en tu trabajo para que haga bien una tarea el primer día? ¿Qué le falta a tu prompt comparado con eso?

F2.2Auditoría de respuestas y detección de sesgos

Verificar no es releer la respuesta y ver si “suena bien”. Es compararla con algo que sabes que es cierto. Algunas técnicas prácticas:

  • Respuestas de referencia: prepara casos con la respuesta correcta conocida y mide cuántos acierta el modelo.
  • Fuentes: pide que cite de dónde saca cada dato y comprueba que la fuente exista y diga eso.
  • Consistencia: haz la misma pregunta de varias formas o varias veces; si cambia la respuesta, desconfía.
  • Pruebas contrafactuales de sesgo: cambia solo un atributo (nombre, género, zona de residencia) y observa si cambia la decisión del modelo.

El sesgo puede venir de los datos de entrenamiento del modelo, de los datos que tú le das o de la forma en que formulas la tarea. Por eso la auditoría revisa las tres cosas.

Ideas clave
  • Sin casos de referencia no hay forma de medir la calidad.
  • Cambiar un solo atributo es la prueba más simple y reveladora de sesgo.
Para pensarSi un asistente evalúa solicitudes de becas, ¿qué atributo cambiarías primero para probar si es justo?

F2.3Metodologías de ideación asistida

La IA es muy buena para generar muchas opciones rápido y mala para elegir la correcta por ti. Úsala en las fases donde la cantidad ayuda y tú decides en las que importa el criterio:

  1. Divergir: pide 20 ideas, enfoques distintos o perspectivas de varios actores (usuario, operador, regulador).
  2. Agrupar: pide que organice las ideas por tema o por tipo de solución.
  3. Criticar: pide los argumentos en contra de cada idea, o que actúe como un evaluador escéptico.
  4. Decidir: elige tú, con criterios explícitos como impacto, factibilidad y riesgo.

Registra qué ideas vinieron de la IA y cuáles del equipo. En la defensa te preguntarán por qué elegiste un camino, y “lo sugirió el modelo” no es una razón.

Ideas clave
  • Divergir con IA, decidir con criterios humanos.
  • Pedir críticas es tan útil como pedir ideas.
Para pensar¿Qué criterio usarías para descartar una idea que el modelo presenta como excelente?

Nombra cuatro partes de un prompt bien estructurado.

Rol y contexto, tarea, datos de entrada delimitados, formato de salida, ejemplos y restricciones (cualquiera cuatro).

¿Por qué conviene cambiar una sola cosa a la vez al mejorar un prompt?

Porque así sabes qué cambio causó la mejora o el empeoramiento al comparar con los mismos casos.

¿Qué es una prueba contrafactual de sesgo?

Repetir la misma entrada cambiando solo un atributo, como el nombre o el género, para ver si cambia la decisión del modelo.

¿Qué es few-shot?

Incluir en el prompt uno o pocos ejemplos resueltos para mostrar al modelo el formato o el criterio esperado.

En una sesión de ideación, ¿qué parte no debes delegar en la IA?

La decisión final, que debe basarse en criterios explícitos del equipo.

DIY WORKSHOP · F2

Laboratorio de prompts con evidencia

Diseña un repertorio de prompts para una tarea real, pruébalo con casos de referencia y audita si hay sesgo. Produce el entregable de F2.

3–4 horasIndividual o en parejaTécnica: Docker + Ollama
Ruta técnica
Evalúa variantes de prompt con un script
  1. Elige una tarea de clasificación, por ejemplo, ordenar consultas ciudadanas en trámite, queja, información u otro.
  2. Escribe 20 casos en casos.csv con la etiqueta correcta. Usa textos inventados, sin datos personales.
  3. Escribe tres versiones del prompt en prompts/v1.txt, v2.txt y v3.txt: una básica, una con formato de salida fijo y una con dos ejemplos (few-shot).
  4. Con el modelo de F1 en Ollama, escribe evaluar.py: para cada versión y cada caso, pide la etiqueta con "options": {"temperature": 0} y compárala con la correcta. Imprime la exactitud de cada versión.
  5. Prueba de sesgo: toma cinco casos, cambia solo el nombre o el género de quien escribe y comprueba si cambia la etiqueta.
  6. Haz commit de cada versión del prompt para que el historial muestre cómo mejoraste.
Ruta complementaria
Repertorio de prompts y rúbrica de calidad
  1. Elige tres tareas de tu disciplina: por ejemplo, resumir un informe, redactar una respuesta a un usuario y extraer datos de un documento.
  2. Para cada tarea, escribe el prompt con la estructura de F2.1 y define una rúbrica de 1 a 3 en exactitud, formato y tono.
  3. Prueba cada prompt con cinco entradas distintas en un asistente de IA y califica cada respuesta con tu rúbrica.
  4. Mejora el prompt que peor puntuó y vuelve a probarlo con las mismas cinco entradas.
  5. Audita un caso: cambia un atributo personal en la entrada y documenta si cambió la respuesta.
Entregable

Repertorio de prompts validados (con su versión final, su propósito y su puntuación) y un informe de auditoría de una o dos páginas sobre la exactitud y el sesgo observados en el caso de estudio.

Lista de verificación
  • Cada prompt tiene casos de prueba y un resultado medido.
  • Puedes mostrar la versión anterior y explicar qué cambió.
  • La prueba de sesgo cambia un solo atributo.
  • No usaste datos personales reales.
